## 一、项目概述（一句话定位，可放简历开头）

基于 **LVGL + Linux** 的**跨端 FTP 文件传输系统**：**客户端交叉编译移植到 RK3568 开发板（ARM Linux）**，通过帧缓冲（FBDEV/DRM）+ 触摸屏实现板端 GUI 与文件上传下载；**服务端运行于 Linux，采用 epoll Reactor + 线程池高并发架构，并用 TUI 实时监控面板（共享内存驱动）展示在线客户端状态**。

## 二、项目职责（按真实项目重写）

1. 基于 Linux **Socket 编程**实现 FTP 文件传输客户端，并**交叉编译移植到 RK3568 开发板（ARM Linux）**，通过 FBDEV/DRM 帧缓冲与触摸屏输入实现板端文件传输 GUI；
2. 基于 **LVGL** 开发客户端图形界面（登录、文件管理器、传输进度弹窗），并与服务端完成协议联调；
3. 在 Linux 服务端以 **TUI** 实现 FTP 服务器：采用 **epoll Reactor + 线程池** 高并发架构，通过**共享内存**驱动实时监控面板；
4. 设计自定义应用层协议（控制/数据连接分离、分包帧格式、递归列目录），保证客户端与服务端可靠通信。

> 注：你给的模板里「BMP/JPG 图片显示与循环播放」在本项目中**并未实现**（当前 UI 是文件管理器，图片解码器虽在 `lv_conf.h` 中开启但未接预览/轮播逻辑），简历不要照抄，见第五节。

## 三、技术要点（简历核心，建议直接复用）

### A. 客户端（RK3568 / ARM Linux + LVGL）

- **RK3568 板级移植与交叉编译**：将 LVGL 客户端**交叉编译部署到 RK3568（Rockchip，四核 Cortex-A55，Mali-G52）开发板**，运行于 ARM Linux；显示后端对接板载 **FBDEV / DRM** 帧缓冲，输入对接 **evdev 触摸屏**（`/dev/input/event6`），完成从 PC 仿真到真机落地的完整移植。
- **Linux Socket 文件传输**：基于 **TCP Socket** 实现自定义 FTP 风格应用层协议（LOGIN / LS / GET / PUT / BYE 等命令，命令号以枚举对齐服务端 `protocol.h`），支持登录鉴权、远程/本地文件浏览与**上传/下载**。
- **多线程并发传输**：采用「1 个主网络线程 + 3 个传输工作线程」的**线程池**；用**环形缓冲区**实现生产者-消费者任务队列，`pthread_mutex` + `pthread_cond` 保证线程安全与阻塞唤醒，支持多文件批量传输与中途取消。
- **可靠落盘与线程安全 UI**：下载时本地 `open` 建 fd、分块 `write()` 落盘，`stat` 预取大小算进度；进度经 `lv_async_call()` **异步投递到 UI 线程**，规避 LVGL 非线程安全；进度上报节流（变化 <1% 跳过刷新）。

### B. 服务端（Linux + TUI，epoll Reactor + 线程池）

- **高并发网络架构**：服务端采用 **epoll Reactor（事件驱动）+ 线程池** 模型，主线程用 epoll 监听多客户端连接与 IO 事件，将任务派发到线程池处理，支撑多客户端并发传输。
- **TUI 实时监控面板（共享内存驱动）**：自研文本界面（ANSI 转义码彩色输出），通过 **System V / POSIX 共享内存（ipc_shm）** 在监控线程与工作线程间共享客户端状态；每秒 `system("clear")` 刷新，按状态着色（绿=空闲 / 黄=下载中 / 红=上传中）展示在线客户端。
- **自定义分包协议**：固定 **8 字节帧头 + 负载** 的报文格式（`read_packet` / `send_packet`），负载长度用 **小端 LE32** 编码；区分**控制连接与数据连接握手（GET_DATA / PUT_DATA）**，并支持 **LISTDIR 递归目录列举**。
- **并发安全的鉴权**：服务端从 `users.conf` 校验账号密码，使用 **`flock` 共享锁（LOCK_SH）** 保证多进程/多线程并发读取时的一致性。

### C. 显示与图像（客户端）

- **帧缓冲显示后端**：客户端显示层采用 **LVGL Linux FBDEV / DRM 驱动**（`lv_linux_fbdev_create` / `lv_linux_drm_create`），底层对 `/dev/fb0` 做 `mmap` 映射实现直接刷屏；PC 端保留 **SDL2** 仿真联调。
- **图像解码能力已就绪**：`lv_conf.h` 已开启 **BMP / JPEG(TJPGD) / GIF** 解码器与 **FreeType** 字体，可作为后续图片预览功能的底座（当前未接预览逻辑）。

## 五、简历真实性校验与风险提示（重要，面试前必看）

1. **模板里的「BMP/JPG 显示与循环播放」本项目未实现**：客户端 UI 是文件管理器，代码里没有图片预览/轮播逻辑（已 grep 确认无 `lv_img_set_src` / 预览 / 双击查看）。简历**不要写**图片显示与循环播放，否则面试被问「怎么解码、怎么轮播」会答不上来。
   - 若想加该功能：可在文件管理器做「双击图片 → `lv_image` 预览」，BMP/JPEG 解码 LVGL 已支持，工作量不大，我可帮你写。

2. **「libjpeg」实际是 TJPGD**：`lv_conf.h` 中 `LV_USE_LIBJPEG_TURBO = 0`，实际开启 `LV_USE_TJPGD`（Tiny JPEG Decoder，libjpeg 轻量替代）。即便以后写图片功能，措辞也要对齐。

3. **「帧缓冲」是 LVGL 封装，不是裸写 mmap**：代码通过 `lv_linux_fbdev_create()` 走 LVGL 的 FBDEV 驱动，而非你自己 `open("/dev/fb0") + mmap` 手写刷屏。安全写法：「基于 LVGL 的 Linux FBDEV/DRM 帧缓冲驱动实现显示」。追问时能讲清 `/dev/fb0` → `mmap` → 按像素格式写显存即可。

4. **「视频」只有传输、没有播放**：传输层支持任意文件（含视频）上传下载，但无视频解码/播放（`lv_conf.h` 里 FFmpeg 选项是关的）。简历写「支持文件（含图片/视频）传输」即可，不要写「视频播放」。

5. **✅ 已确认：客户端已移植到 RK3568 开发板（真 ARM 硬件）**，此前的「未上板」风险已消除。简历可放心写「交叉编译移植到 RK3568 / ARM Linux」，建议附一张板子实跑文件传输的截图或录屏佐证。

## 六、嵌入式岗位面试深挖准备（针对本项目）

- **RK3568 / 移植**：用什么交叉编译工具链（如 aarch64-linux-gnu-gcc）？编译链怎么配？板子怎么跑（NFS / SD 卡 / scp）？FBDEV 与 DRM 区别？触摸屏走 evdev 还是 tslib？
- **网络（服务端重点）**：**epoll 的 LT 与 ET 区别**、为什么用 Reactor 模式、线程池如何与 epoll 配合（one loop per thread / 任务队列）、惊群问题；**共享内存 IPC** 的创建/映射（shmget/shmat 或 shm_open+mmap）、与管道/消息队列对比；`flock` 与 `fcntl` 锁区别。
- **网络（客户端重点）**：TCP 三次握手、线程池为什么用条件变量、生产者-消费者模型、`lv_async_call` 为什么能线程安全回 UI。
- **帧缓冲/显示**：`/dev/fb0` 是什么、`mmap` 原理、RGB888 / RGB565 / BGR 像素排列、双缓冲 vs 局部刷新。
- **C/系统**：`malloc/free` 配对、文件描述符泄漏、多线程竞态、环形缓冲区实现、共享内存生命周期。
